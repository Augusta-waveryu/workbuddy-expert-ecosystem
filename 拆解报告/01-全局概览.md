> 数据基准：2026-08-19，**421 个专家插件包已全量安装到本地**，统计基于真实文件系统扫描而非清单声明。

## 1.1 一句话结论

整个体系是 **三层结构**：`专家(展示层清单)` → `插件包(可下载单元)` → `构件(agents / skills / rules / scripts / mcp / hooks)`。
能力标签只是清单里的展示元数据，真正决定行为的是插件包里的 **agent 提示词 + 私有 skill**。

## 1.4 调用模型

1. 用户选专家 → 读清单拿到 `plugin` + `agentName`
2. `resolveExpertLocation()` 在多市场中查 manifest；本地无 → `activateExpert()` 下载解压
3. 加载 `agents/<agentName>.md` 作为系统提示词（人格 + 流程 + 输出规范）
4. 合并 `rules/` 为硬约束；把 `skills/` 注册进该会话可用工具集
5. 模型按 skill 的 `description` 字段自主路由调用

> 决定「实际执行差异」的正是第 3、4 步 —— 同一个 skill 被不同专家调用时，外层提示词与 rules 不同，产出形态就不同。详见 05。

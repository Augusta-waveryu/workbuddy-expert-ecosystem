# 04 · 关键 Skill 实现机制深度复盘

> 目标：从已安装的技能里挑出**最值得学习实现机制**的几个，拆它们的「触发 → 编排 → 产出」链路，提炼可复用的套路，便于你自己组建专家团 / 写新技能。
> 覆盖范围：1 个代码型（wechat-article-search）+ 4 个提示词型（stock-deep-dive / morning-note / research-synthesis / sql-queries）。前者有可执行脚本，后四者是**纯提示词驱动的工作流**。

---

## 一、先建立一个核心认知：Skill 只有两种实现形态

| 形态 | 判定 | 适用 | 例子 |
|---|---|---|---|
| **代码型** | 目录内含 `scripts/`（.py/.sh/.js） | 要调外部 API、爬网页、跑计算、生成文件 | wechat-article-search |
| **提示词型** | 只有 `SKILL.md`（+ 可选 `references/`） | 需要结构化推理/写作/分析的工作流 | 其余 4 个及绝大多数研究/金融技能 |

无论哪种，Skill 的**前半段都是同一套**：`SKILL.md` 顶部的 `frontmatter`——

```yaml
---
name: xxx
description: <何时触发、做什么>   # ← 这是 skill 的"开关"，agent 靠这段自然语言决定调不调它
---
```

**经验 1：description 就是路由规则。** 写得越像"触发条件清单"，越容易被正确调用。对比两个写法：
- 差：`description: 股票分析工具`（agent 不知道什么时候用）
- 好（stock-deep-dive）：`当直接命中或高相似度命中这些领域时…本技能不适用于：大盘分析、行业整体研究、宏观解读…`（明确正向 + 反向边界，路由极准）

## 二、代码型范本：wechat-article-search（已实跑验证）

路径：`plugins/marketplaces/cb_teams_marketplace/plugins/deep-research/skills/wechat-article-search/`
结构：`SKILL.md` + `scripts/sogou_search.py`(364 行) + `references/api_reference.md`

**值得学的 3 点：**

1. **反爬集中在一个类里**（`RateLimiter`，L28-97）
   - 随机 UA 池 + 请求间隔抖动 0.5–1.5s + SUV Cookie 每 50 次轮换。
   - 要点：**限频逻辑与业务代码解耦**，改策略只动一个类。
2. **中转跳转再抓正文**（`get_article_content`，L209-258）
   - 搜狗列表 → `/link?url=` 中转页 → 还原 `mp.weixin.qq.com` 真实地址 → 抽 `<div id="js_content">` 正文。
   - 这是公众号抓取的标准两段式，复用价值高。
3. **零外部依赖**：纯 `urllib/re/argparse`，到哪都能跑。

**实战踩坑（已验证）：**
- 文档吹的"并发""最多 100 条"都是假的：代码 L319 写死 `min(count,10)`，且全程顺序执行。
- **读原文功能已坏**：实测 `获取 1/1... 失败: 无法解析微信文章链接`——搜狗改了中转页格式，L216 的 `url += '...'` 正则匹配不上。= 代码型技能也会因外部站点改版而过期，需维护。

> 结论：代码型技能"能力最强但最脆"，依赖外部站点稳定性，必须有人维护。

## 三、提示词型范本 1：stock-deep-dive（边界 + 工作流 + 产出契约）

路径：`a-share-analysis/skills/stock-deep-dive/`，被「A股研究团队」专家引用。
纯提示词，92 行，但结构是**教科书级的研究技能模板**：

```
① 适用边界（正向清单 + 反向清单）   ← 决定"该不该接"
② 数据获取（委托给 finance-data plugin） ← 职责分离：技能只管分析，数据由另一个插件供给
③ 五步工作流：确认标的 → 定主题 → 取数 → 输出 → 规范
④ 输出规范：强制要求 + 严禁出现（"仅供参考""注："等套话一律禁止）
```

**值得学的 3 点：**
- **显式写"不使用本技能的情形"**：避免技能被错用（如把它拿去做大盘分析）。这是路由正确性的后半段。
- **数据与逻辑分离**：技能本身不存数据，写"通过 finance-data plugin 获取"。= 你可以把"取数"做成独立插件，多个分析技能共用。
- **输出契约（严禁出现…）**：用"禁止清单"直接卡掉废话，比"请简洁"有效 10 倍。这是控制 LLM 输出质量的硬招。

## 四、提示词型范本 2：morning-note（观点化 + 固定版式）

路径：`equity-research/skills/morning-note/`，被「股票研究专家」引用。
89 行，金融晨报工作流。

**值得学的 2 点：**
- **"Be opinionated" 原则**（L84）：`morning notes that just summarize news without a view are useless`。用一句强指令逼模型给判断，而不是复述。
- **固定版式 + 长度约束**：`Top Call → Overnight → Key Events → Trade Ideas`，且 `readable in 2 minutes`、`1 page max`。= 给 PM/交易员看的产出，格式和篇幅就是需求本身。

可复用到任何"日报/周报/简报"类技能。

## 五、提示词型范本 3：research-synthesis（斜杠命令 + 连接器感知）

路径：`design-to-code/skills/research-synthesis/`，被设计类专家引用。
92 行，但有两个**进阶机制**值得学：

1. **斜杠命令式调用**
   ```yaml
   ---
   name: research-synthesis
   argument-hint: "<research data, transcripts, or survey results>"
   ---
   /research-synthesis $ARGUMENTS
   ```
   = 技能可以设计成"用户主动敲命令 + 带参数"，而不只是被动触发。适合你希望人工精确投放输入的场景。

2. **连接器感知（Connector-aware）**
   ```
   If ~~user feedback is connected: 拉工单/NPS 补充
   If ~~product analytics is connected: 用量化数据验证
   If ~~knowledge base is connected: 比对历史研究并发布
   ```
   = 技能能根据"当前连了哪些外部系统"自动扩展能力。这是**组建专家团时最关键的联动方式**：一个研究技能可以"如果连了飞书就写回多维表格，连了 obsidian 就存库"。

3. **输出模板即契约**：直接给 markdown 骨架（Executive Summary / Themes / Insights→Opportunities 表 / Segments / Recommendations），模型填空。= 复杂产出用"骨架+占位"比"自由发挥"稳得多。

## 六、提示词型范本 4：sql-queries（把知识库塞进 SKILL.md）

路径：`data/skills/sql-queries/`，被「智数分析专家团」等引用。
**427 行，全场最长，但几乎没有"指令"，全是知识。**

**值得学的 1 点：**
- **把领域知识嵌入式写进 SKILL.md**：覆盖 PostgreSQL/Snowflake/BigQuery/Redshift/Databricks 五种方言的日期/字符串/JSON/数组写法 + 通用窗口函数/CTE/留存/漏斗/去重模板 + 错误处理清单。
- 好处：模型无需外部查文档即可写出跨方言正确 SQL；坏处：SKILL.md 会变成"大词典"，需随方言版本更新。
- 适用边界：当技能的核心是"知识"而非"流程"时，直接把知识当上下文喂进去，比外挂 references 更省事（references/ 适合超长文档，SKILL.md 适合高频要用到的速查）。

## 七、提炼：写一个新技能 / 组专家团的 6 条可复用套路

1. **description 写"触发+反触发"**：正向列场景、反向列禁区，路由最准。
2. **两种形态二选一**：要碰外部系统→`scripts/` 代码型；要推理/写作→纯提示词型，别混。
3. **输出契约用"禁止清单"**：比"请简洁"硬。stock-deep-dive 的"严禁出现…"直接抄。
4. **职责分离**：取数、分析、成文拆成不同 skill/plugin，多个专家复用同一取数插件（如 finance-data）。
5. **连接器感知**：在 SKILL.md 写 `If ~~xxx connected: …`，让专家团能随接入的系统自动扩能。
6. **版本会过期**：代码型依赖外部站点（wechat-article-search 读原文已坏）；知识型依赖方言/API 版本（sql-queries 需随版本更新）。两者都要有人维护。

## 八、对你"组建自己专家团"的直接建议

- **最小可用专家团 = 1 个人设提示词(agent) + N 个技能(skills) + 可选规则(rules) + 可选连接器。**
- 复用路径：直接 copy `a-share-analysis/skills/` 下 20 个金融技能改 description 即可成"你自己的投研团"；把 `research-synthesis` 的"斜杠命令+连接器感知"模式套到你的调研场景。
- 加新能力：在插件目录新建 `skills/<your-skill>/SKILL.md`（代码型再加 `scripts/`），或在 `plugin.json` 的 `skills[]` 注册（注意：很多插件是 skills/ 平铺自动发现，不写 plugin.json 也能被加载，见 02 文档说明）。

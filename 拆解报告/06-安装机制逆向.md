# 06 · 安装机制逆向：「点击召唤」到底做了什么

> 本章回答：**点击召唤算安装吗？能否绕过 GUI 批量安装？**
> 结论：召唤 = 下载插件包并注册进本地市场清单，**是真安装**；且存在一条公开、可枚举的旁路，已用它一次性装完 421 位专家。

---

## 6.1 结论摘要

| 问题 | 答案 |
|---|---|
| 点击「召唤」算安装吗？ | **算。** 它触发 `ExpertPluginService.ensureDownloaded()` → 下载 tar.gz/zip → 解压到 `experts/plugins/<name>/` → 增量回写 `marketplace.json` |
| 召唤和 CLI `plugin install` 是同一件事吗？ | 本质相同（都落到同一目录 + 同一清单），但**入口不同**：召唤走运营平台签名 URL，CLI 只认本地市场清单里已存在的条目 |
| 为什么 CLI 装不了没召唤过的专家？ | `experts` 市场是 `type: directory`，其 `marketplace.json` 标注 `auto-generated`，**只包含已下载的包**。CLI 查不到条目就报 not found |
| 有没有批量安装的办法？ | **有。** 官方代码里留了一条无签名的 COS 回退源，可直接枚举下载全部 421 个包 |

---

## 6.2 逆向路径（可复现）

### 第 1 步：确认召唤的落地位置

```bash
ls ~/.workbuddy/plugins/marketplaces/experts/plugins/
# 每个已召唤专家一个目录，内含 .downloaded_at 时间戳
cat ~/.workbuddy/plugins/marketplaces/experts/plugins/llm-wiki/.downloaded_at
# 2026-06-10T14:01:47.747Z
```

`.downloaded_at` 的存在直接证明：召唤 = 一次真实的下载落盘动作。

### 第 2 步：从主进程日志抓下载地址

日志目录 `~/Library/Logs/WorkBuddy/main.log`，作用域 `daemon-server:expert-market`：

```json
{"scope":"daemon-server:expert-market","message":["expert bundle download start",{
  "bundleName":"workspace-builder",
  "source":"operation-platform",
  "bundleUrl":"https://openplatform-cdn.codebuddy.cn/openplatform/experts/<uuid>/eu_<hash>.zip?<redacted>"
}]}
```

三个关键信息：

1. `source: "operation-platform"` —— 不走 `download.codebuddy.cn/plugin-marketplace`
2. URL 含**随机 UUID + 不可推导的 `eu_<hash>` 文件名**
3. 查询串被 `redactUrlForLog()` 脱敏 —— 是**预签名 URL**

> 这一步说明：**照抄日志里的 URL 没用**（签名会过期），也**推不出**其他专家的地址。

### 第 3 步：找到下发签名 URL 的 API

同一份日志里，skill 侧的请求**没有脱敏**，暴露了完整 API 契约：

```
POST https://copilot.tencent.com/v2/operation-platform/market/skill/download-url
Headers: Content-Type: application/json
         Authorization: Bearer <token>
         X-User-Id: <uuid>
         X-Domain: www.codebuddy.cn
Body:    {"skill_id":"skill_2053083151135014912","version":"1.0.3"}
→ {"code":0,"data":{"download_url":"...?sign=1787102419-...","expires_at":1787188819026}}
```

同族端点：`market/skill/list`、`market/skill/get-by-ids`、`market/categories`。
按对称性推测 `market/expert/list` / `market/expert/download-url` 存在，但**这条路走不通**：

- token 存在 Electron `safeStorage`（钥匙串 `WorkBuddy Safe Storage` 加密），日志里只有掩码 `Bearer ****q5ug`
- 日志里唯一未掩码的 43 字节 token 是 **sidecar 会话 token**，打到 APISIX 网关直接 401
- 本地 daemon（`127.0.0.1:58805`）所有猜测路径均 404，非 REST 风格

### 第 4 步：检查深链通道

`Info.plist` 注册了 scheme `workbuddy`。在 `app.asar` 中检索到完整深链路由表：

```
workbuddy://codebuddy-ide/expert/install?expertname=xxx&sharecode=xxx&channelType=expert
workbuddy://codebuddy-ide/skill/install?skillname=xxx&downloadurl=xxx
workbuddy://task?action=start&prompt=...&cwd=...&skills=...&connectorIds=...
workbuddy://switch-model?modelId=xxx
workbuddy://conversation/open?sidebarUrl=<encoded>&promptContentBlocks=<JSON>&taskId=<id>
workbuddy://my-files?tab=cloudFiles
workbuddy://home  ·  workbuddy://agentmail  ·  workbuddy://wechat/share
```

源码注释明确了 `/expert/install` 的定位：

> 自定义专家导入专用路径，与 skill 安装流程解耦
> 鉴权字段独立：`sharecode`（避免 access_token 暴露）

`tryHandleExpertInstallDeepLink()` 里 `if (!expertName || !shareCode) return false` ——
**`sharecode` 必填**，这是「自定义专家分享导入」通道，**不适用于市场的 421 位官方专家**。

> 顺带发现：`/skill/install` 接受任意 `downloadurl` 参数，是个值得注意的设计。

### 第 5 步：找到突破口 —— 官方留的无签名回退源

在 `app.asar` 里定位 `ExpertPluginService.downloadAndExtract()`：

```js
const source = explicitBundleUrl ? "operation-platform" : "cos";
const bundleUrl = explicitBundleUrl
  || buildExpertUrl(`/bundles/${bundleName}.tar.gz`);   // ← 回退分支
```

继续找 `buildExpertUrl` 的基址：

```js
var EXPERT_CENTER_COS_CONFIG = {
  baseUrl: "https://acc-1258344699.cos.accelerate.myqcloud.com/workbuddy/expert-marketplace",
  manifestPath: "/expert_center.json",
  featuredScenesPath: "/featuredScenes.json",
  download: { timeout: 3e4, maxRetries: 1, retryDelay: 1e3, batchConcurrency: 10 }
};
function buildExpertUrl(path) { return `${EXPERT_CENTER_COS_CONFIG.baseUrl}${path}`; }
```

**这是一个公开 COS 存储桶，无签名、无鉴权、路径完全可推导。**

```bash
B=https://acc-1258344699.cos.accelerate.myqcloud.com/workbuddy/expert-marketplace
curl -s "$B/expert_center.json" | head -c 200        # HTTP 200, 1.1 MB, 421 位专家
curl -sI "$B/bundles/llm-wiki.tar.gz"                # HTTP 200
```

`expert_center.json` 里每位专家都有 `plugin` 字段 → 即 bundle 名 → 拼出下载地址。**至此全量可枚举。**

## 6.3 三条安装通道对比

| 通道 | 入口 | 覆盖范围 | 鉴权 | 可批量 |
|---|---|---|---|---|
| **GUI 召唤** | 点击专家卡片 | 全部 440 位 | 运营平台预签名 URL | ❌ 逐个点 |
| **CLI `plugin install`** | `codebuddy plugin install <name>@experts` | 仅本地清单已有的条目 | 复用本地登录态 | ⚠️ 需先有条目 |
| **COS 公开源** | `bundles/<plugin>.tar.gz` | **421 位**（19 位仅运营平台有） | 无 | ✅ **本次采用** |

## 6.4 本次批量安装实施

复刻官方 `downloadAndExtract()` 的逻辑，脚本要点：

```python
BASE = "https://acc-1258344699.cos.accelerate.myqcloud.com/workbuddy/expert-marketplace"
CONCURRENCY = 10    # 对齐官方 batchConcurrency
TIMEOUT     = 30    # 对齐官方 download.timeout = 3e4 ms

# 1. 拉清单，取 plugin 字段作为 bundle 名
# 2. 并发下载 bundles/<name>.tar.gz
# 3. 解压前校验 tar 成员路径，拒绝绝对路径与 ".." （防路径穿越）
# 4. normalizeExtractedPluginRoot：单层目录则上提一层
# 5. 校验 .codebuddy-plugin/plugin.json 存在，否则判失败
# 6. 写 .downloaded_at，原子 move 到目标目录
# 7. 全量重建 marketplace.json（name / source / description）
```

**执行结果**

| 指标 | 值 |
|---|---|
| 耗时 | 48 秒 |
| 清单专家 | 421 |
| 成功安装 | **421**（缺失 0，多余 0） |
| `plugin.json` 校验通过 | 421 / 421 |
| `marketplace.json` 条目 | 12 → **421** |
| 落盘体积 | 1572.3 MB / 16485 文件 |

**CLI 端到端验证**


## 6.5 未覆盖的 19 位内部专家（含可见性机制）

这 19 位只在本地 440 清单里，公开 COS 的 421 清单中没有。进一步分析发现 manifest 每个专家带 `visibility` 字段，**真正决定"外部账号能否召唤"的不是有无公开包，而是该字段 + 服务端下发**：

- `internal_only`（12 位）：**仅腾讯内部可见**，外部 GUI 不展示、不可召唤
- `external_only`（2 位）：外部可见、可召唤（送报报、MigraQ）
- 无标记（5 位）：理论上默认可见，但问图/甄需明/云知知识评审实测外部搜不到 —— 受 `isOPC`（面向特定产品/渠道，88 位）与服务端白名单控制

## 6.6 值得学习的工程设计

| 设计 | 位置 | 价值 |
|---|---|---|
| **双源降级** | `explicitBundleUrl \|\| buildExpertUrl(...)` | 运营平台挂了自动回退公开 COS，可用性兜底 |
| **URL 脱敏日志** | `redactUrlForLog()` | 签名串不落日志，但保留 host+path 便于排障 —— 值得抄 |
| **可信源白名单** | `isTrustedDownloadUrl()` | 拒绝非白名单域，防止深链传入恶意 `downloadurl` |
| **增量清单回写** | `updateMarketplaceManifest(bundleName)` | 只改一条，不全量扫目录，避免并发写冲突 |
| **下载去重锁** | `downloadingExperts: Map<name, Promise>` | 同一包并发请求复用同一 Promise，天然幂等 |
| **陈旧判定** | `isLocalStale(localPath, updatedAt)` | 用远端 `updatedAt` 比本地 `.downloaded_at`，避免无效重下 |
| **解压根归一** | `normalizeExtractedPluginRoot()` | 兼容 tar 打包时多一层目录的历史包 |

> 反面教训：**公开 COS 桶导致全部专家提示词可被匿名下载**。
> 签名通道做得再严，只要留了无签名回退源，前者的防护就形同虚设。

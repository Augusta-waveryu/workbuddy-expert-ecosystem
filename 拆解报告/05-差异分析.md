# 05 · 差异分析：同标签 / 同技能，差在哪

> 本章回答两个问题：
>
> 1. 多位专家挂着**同一个能力标签**，差异是什么？
> 2. 多位专家调用**同一个 skill**，执行差异是什么？

数据基础：421 位专家的真实代码已全部落地本地，其中 84 个标签被 ≥2 位专家共用，78 个私有 skill 被 ≥2 位专家携带。

## 5.1 分析框架：差异发生在四个层次

| 层次 | 载体 | 是否影响执行 | 说明 |
|---|---|---|---|
| L0 展示层 | `tags[]`、`profession`、`description` | ❌ 完全不影响 | 纯元数据，只用于市场检索与卡片展示 |
| L1 人格层 | `agents/<name>.md` | ✅ **最主要** | 系统提示词：角色设定、工作流、输出格式、禁止事项 |
| L2 约束层 | `rules/*.md` | ✅ 强 | 硬性规则，优先级高于人格层的软约束 |
| L3 工具层 | `skills/`、`mcp/`、`scripts/` | ✅ 决定能力边界 | 有没有这个工具、以及是私有版还是全局版 |
| L4 编排层 | `members[]`（专家团） | ✅ 决定协作路径 | lead 分派 → member 执行 → lead 汇总 |

> **结论先行**：标签相同 ≠ 能力相同。真正的差异 100% 来自 L1–L4。同一个 skill 被不同专家调用时，skill 本身的代码一样，但 **外层提示词不同 → 传参不同 → 产出形态不同**。

### 5.2.3 同标签差异的四种典型模式

1. **深度差**：一方纯提示词（0 私有 skill），另一方自带 10+ 专业 skill。例：`数据分析` 标签下，轻量专家只靠 agent.md 讲方法论，`DatabrainAgentV2` 带 11 个 skill 直连数据平台。
2. **编排差**：单体 agent vs 专家团。团队型把同一标签拆成 lead+member 分工，产出更结构化但更慢。
3. **领域差**：标签同名但垂类不同。例：`竞品分析` 在产品经理手里是功能矩阵，在投行专家手里是 `comps-analysis` 可比公司估值。
4. **约束差**：有 `rules/` 的专家会拒绝越界（如法务专家强制加免责声明），无 rules 的专家更自由。

### 5.3.2 执行差异的产生机制

同一份 skill 代码，产出不同的**四条通路**：

| 机制 | 说明 | 可观察证据 |
|---|---|---|
| ① 调用时机不同 | agent.md 规定的工作流位置不同：有的第一步就查，有的最后才验证 | 对比同名 skill 拥有者的 agent.md 工作流章节 |
| ② 传参偏好不同 | 提示词预设了默认参数（时间窗、市场、语言、输出格式） | agent.md 中对该 skill 的调用示例 |
| ③ 后处理不同 | 拿到同样原始数据后，套用不同的分析框架与模板 | agent.md 的「输出格式」章节差异 |
| ④ 同名覆盖 | 专家私有 skill 与全局 skill 同名时，加载专家包内版本 | `skills/<name>/SKILL.md` 文件内容对比 |

> 机制 ④ 最容易被忽略：`humanizer`、`github`、`deep-research` 等既存在于全局池，也被多个专家包私有携带。**私有版优先**，所以「同名 skill」可能根本不是同一份代码。

## 5.4 如何自己做这个对比（可复现步骤）

```bash
MP=~/.workbuddy/plugins/marketplaces/experts/plugins

# 1. 找出哪些专家携带同名 skill
for d in $MP/*/skills/*/; do echo "$(basename $d)  <-  $(basename $(dirname $(dirname $d)))"; done \
  | sort | awk '{print $1}' | uniq -d

# 2. 对比两个专家包里同名 skill 的实际内容
diff $MP/investment-banking/skills/dcf-model/SKILL.md \
     $MP/pitch-agent/skills/dcf-model/SKILL.md

# 3. 对比外层人格提示词（真正的差异来源）
wc -l $MP/investment-banking/agents/*.md $MP/pitch-agent/agents/*.md
```
